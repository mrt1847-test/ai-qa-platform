# QA Studio 인터랙티브 프런트 샘플

[UI_SPEC v0.5 보관본](../docs/history/v0.5/UI_SPEC.md)를 직접 눌러보며 검토하기 위한 **폐기 가능한 UI 샘플**입니다. 제품 코드/DB/AI runner의 구현이 아닙니다. 외부 라이브러리·패키지 설치 없이 동작합니다.

현재 [v0.6 실행 설계](../docs/superpowers/specs/2026-10-31-replay-and-self-healing-design.md)는 코드/동작 재생·선택 AI 검증·셀프힐링 ON/OFF를 추가했다. 이 샘플의 코드는 변경하지 않았으므로 해당 기능을 구현/검증한 화면으로 보지 않는다.

## 열기

- Windows: `start-preview.cmd`를 더블클릭합니다. 설치되어 있는 Node.js로 로컬 정적 서버를 띄우고 기본 브라우저를 엽니다.
- 주소: [http://127.0.0.1:8765](http://127.0.0.1:8765)
- 터미널: 이 폴더에서 `node serve.cjs` 실행. 종료는 해당 터미널에서 Ctrl+C.
- 서버 없이: `index.html`을 브라우저로 직접 열어도 사용할 수 있습니다. 브라우저에 따라 file URL의 저장 동작은 다를 수 있어 로컬 서버를 권장합니다.
- 포트가 사용 중이면 기존 미리보기를 열거나 `QA_DEMO_PORT` 환경변수에 다른 포트를 지정합니다.

## 추천 체험 순서

1. **새 녹화:** Android / Web을 번갈아 선택해 미리보기와 앱/URL 입력 차이를 확인합니다. 필요 정보와 자연어 검증·기대 결과를 입력합니다. 모의 시나리오는 로그인/장바구니 두 가지입니다.
2. **모의 녹화:** 동작을 한 개씩 진행하거나 자동 재생합니다. 각 동작의 전후 화면과 로그가 저장됩니다. 다섯 동작 수집 후 ‘녹화 완료 및 저장’을 선택합니다. 녹화 중 승인 버튼은 없습니다.
3. **부분본 저장:** 동작 두 개만 진행하고 중단합니다. 기록과 새 케이스 버전은 남고 완결성은 미완성입니다. 승인은 차단되며 전체 재녹화로 이어집니다.
4. **저장본 검토:** 케이스의 ‘저장본 검토’를 엽니다. 시범 수행을 PASS로 완료하고 검토로 돌아옵니다. ‘출처 녹화’와 ‘현재 시범’의 동작 다섯 개씩을 각각 확인합니다. ‘이 동작 검토함’을 누르면 다음 미검토 동작으로 이동합니다. 다섯 준비 조건 충족 후 사유를 입력해 승인합니다.
5. **재녹화/승인본 유지:** 기본 예시 `AUT-041`은 v2 승인본과 v4 후보가 있습니다. v4는 이미 시범 PASS이고 동작 검토를 기다립니다. 재녹화 중단/반려 시에도 기본 v2가 유지됩니다. v4 승인 시 기본본만 v4로 전환되며 이전 승인은 유효합니다.
6. **묶음 버전:** ‘테스트 묶음’의 `SUITE-01`은 여전히 v2입니다. ‘구성 갱신’에서 차이를 확인하고 새 suite revision으로 바꿉니다. 이미 접수한 수행은 변경되지 않습니다.
7. **수행/분석:** 승인 케이스를 단독/선택/묶음 실행합니다. 설정창에서 모의 PASS/FAIL/BLOCKED 결과를 고릅니다. 실패 항목에 분석 의견을 저장하거나 PASS로 새 수행을 만들어도 원본 FAIL은 유지됩니다.
8. **리포트:** `RUN-012`는 N=10 / PASS6 / FAIL2 / BLOCKED1 / NOT_RUN1입니다. 완료100%, 검증 통과75%, 전체 통과60%를 비교합니다. 누적 분석의 전체 수행 이력/조건별 최근 완료 결과·대상·기간·시범 포함을 변경하고 CSV로 내보낼 수 있습니다.
9. **설정/보관:** 현재 기본본과 유효한 과거 승인본의 근거 보호를 확인합니다. 샘플 초기화는 직전 복구본을 남깁니다. JSON으로 상태를 내려받을 수 있습니다.

## 동작 범위와 한계

- 화면 구성, 검색/필터/페이지·케이스 버전/초안·기기별 녹화 마법사·동작 기록·시범/검토/승인/반려/철회·재녹화·묶음 revision·수행/취소/재실행·분석 의견·리포트/CSV·프로젝트 선택/생성·선택 TC 추가·보관/활동 이력을 체험합니다.
- 기기 화면은 직접 만든 **합성 HTML 모의 화면**입니다. 실제 PNG 캡처나 녹화 동영상이 아닙니다. 버튼이 실제 ADB/Playwright/모델/클라우드를 호출하지 않습니다.
- 자연어는 그대로 보관하며 AI가 해석하지 않습니다. 로그인/장바구니의 고정 모의 동작과 결과로 상호작용만 재현합니다. 입력한 임의 시나리오의 검증 성공을 보장하지 않습니다.
- 상태는 origin별 `localStorage`의 `aiqa-ui-prototype-v1` 키에 저장됩니다. 실제 SQLite/서버 계정·인증·멀티 사용자 충돌·영구 artifact/GC·백업복원·실시간 화면 제어·모델 비용·엔진 계측은 구현하지 않았습니다. 실제 비밀번호·키·운영 데이터는 입력하지 마세요.
- 새로고침하면 저장된 모의 기록을 불러옵니다. 자동 재생 중 새로고침하면 녹화 재생은 멈추고 수집한 동작부터 버튼으로 이어갑니다. 실제 runner 재개를 의미하지 않습니다.
- 날짜·분포·시도·성능 수치는 모두 샘플입니다. 상세 보고서 인쇄는 브라우저 인쇄 기능입니다. 장기 `as_of`/cursor 재현과 정식 DB 제약은 [DATA_DESIGN](../DATA_DESIGN.md)의 향후 구현 사항입니다.
- 디자인 결정을 검토한 뒤 제품 구현은 기존 [IMPLEMENTATION_PLAN](../IMPLEMENTATION_PLAN.md)의 절차로 별도 진행합니다. 이 파일들을 제품 기반으로 채택했다는 의미가 아닙니다.

## 파일

`index.html` 진입점 / `styles.css` 화면 스타일 / `demo-data.js` 합성 데이터 / `app.js` 브라우저 상태와 상호작용 / `serve.cjs` localhost 전용 정적 미리보기 / `start-preview.cmd` 실행 바로가기.
