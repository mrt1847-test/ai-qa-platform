# PC-01 · 저장 검토와 명시적 offline 실행 차단

2026-11-02 · **complete / core_contract**. [설계](../../superpowers/specs/2026-11-02-managed-pc-execution-design.md) · [카드](../../superpowers/plans/2026-11-02-managed-pc-transition.md#pc-01). 임시 server DB/API의 명시 상태 검사이며 실제 원격 연결·전원 단절 수용이 아니다.

## 변경과 제공 interface

- `src/aiqa/domain/resource_readiness.py`: `resource_readiness(connection, project_id, resource_id, target_kind) -> ResourceReadiness(ready, code, message, job_id)`. project alias로 범위를 한정한 뒤 target·quarantine·inventory state를 조회한다. DB write·장치/모델 호출·예약 없음.
- `recording/service.py:_require_resource`와 `domain/executions.py:_one_item/_rerun_blockers`가 동일 판정을 사용한다. offline/누락/target mismatch/quarantine은 RESOURCE_UNAVAILABLE, busy는 RESOURCE_BUSY다. 녹화는 기존 PreflightRejected/ResourceBusy로 변환한다.
- 기존 rerun이 approval/environment만 확인하고 현재 resource를 재검사하지 않던 누락을 수정했다. 완료 receipt 재조회는 새 실행이 아니므로 이전 결과를 그대로 반환한다.
- review template에 저장본 승인은 실행 PC 연결과 독립이고 기존 필수 근거/시범/보관 조건은 유지한다는 설명을 추가했다. 승인 서비스의 정상 gate는 변경하지 않았다.
- 새 tests `integration/test_managed_pc_admission.py`, `acceptance/test_managed_pc_review.py`. 기존 `acceptance/test_w22.py:_rerun_graph`는 등록 worker/ready resource/target을 가진 유효한 tests-only snapshot으로 보완했다.

## 검증

TDD: quarantine ready 녹화/trial2개와 offline/unauthorized/busy/quarantine rerun4개가 실제로 차단되지 않아 **6 failed /1 passed**를 재현한 뒤 공통 검사를 구현했다. 이후 공개 API에서 준비 preview 후 offline 전환·최초 녹화/재녹화 거부와 rollback·RUN/ITEM/job/candidate write0, formal preview 차단, 다른 project 은닉/target mismatch, 멱등 rerun receipt를 확인했다.

```text
python -m pytest tests/integration/test_w16.py tests/integration/test_w17.py tests/acceptance/test_w17.py tests/integration/test_w19.py tests/acceptance/test_w19.py tests/integration/test_w20.py tests/acceptance/test_w20.py tests/acceptance/test_w22.py tests/integration/test_ux_recording_draft.py tests/acceptance/test_ux_review_journey.py tests/acceptance/test_review_ui.py tests/integration/test_managed_pc_admission.py tests/acceptance/test_managed_pc_review.py -q --tb=short
56 passed in 36.70s
```

이 중 새15개는 임시 DB/API의 계약 검증이다. 저장 graph에는 제품/실기기 자료가 아닌 tests-only 근거를 썼다. worker/resource가 없는 서버 DB에서 정상 저장 근거 승인201과 script 근거 누락 승인422, 새 queued job0을 확인했다. 실제 운영 DB/파일은 열거나 변경하지 않았다.

설계 builder check는 중요한 미답 질문 없음, 독립 code review는 Critical/Important 결함 없음이었다. 검토가 제안한 공개 API 재녹화 rollback·preview→offline·project/target·formal blocker 검사를 추가해 최종56개에 포함했다. 설치/모델 호출/실제 dispatch/외부 공개/배포0.

## 남은 범위와 다음 작업

**PC-02**가 server-received heartbeat·last_seen·등록 폐기/worker boot/session·45초 만료와 admission/claim 통합을 구현한다. 현재는 inventory에 ready가 남은 PC의 전원 단절을 자동 감지하지 못한다. 따라서 이 완료를 ‘PC를 실제로 꺼도 전체 서비스 요구 충족’으로 해석하지 않는다.

PC-03은 상태/버튼 UI, PC-04는 원격 소비/드라이버·격리/정제 spool ACK·중앙 인증/독립 저장/운영 배포·실제 PC 종료 E2E의 작은 후속 카드를 소유한다. 관리 서버가 실행 PC와 같은 PC에서만 도는 개발 배치로는 offline 조회/승인 운영 수용이 불가하다. 추가 호스팅·도메인 선택과 실제 접속 근거가 필요하며 아직 수행하지 않았다.
