# PC-03 · 실행 PC 상태와 조회·실행 행동

2026-11-03 (Asia/Seoul) · core_contract · [구현 카드](../../superpowers/plans/2026-11-02-managed-pc-transition.md#pc-03)

- 환경 목록과 녹화·시범 준비 화면은 서버가 판정한 연결 상태, 마지막 응답 시각, 기기 상태와 실행 제한 사유를 표시한다. 저장된 최근 관찰의 시각과 PC 응답 시각을 분리했다. 재실행 화면은 선택한 범위의 저장 스냅샷에 있는 기기를 확인한다.
- 자원 목록은 브라우저의 프로젝트 세션으로 읽으며 캐시하지 않는다. 초기 표시 이후 10초마다, 화면에 포커스가 돌아올 때와 준비 검사 시에 갱신한다. 연결 확인 응답을 받지 못하면 새 실행을 비활성화하고 입력은 보존한다. 준비 검사 결과는 선택이나 연결 상태가 달라지면 다시 확인한다.
- 실제 임대가 있으면 기기 점유를 표시한다. 종료된 작업의 임대가 남아 있으면 기기 정리 확인이 필요하다고 표시한다. 임대 해제와 실제 기기 정리 검증은 원격 워커 연결과 함께 수용한다.
- 오프라인에서도 초안 편집·저장과 서버 저장본 조회·검토·승인을 이용할 수 있다. 재녹화 준비는 초안으로 이어지고 실제 시작은 연결 상태에 따라 비활성화한다. 현재 정식 수행 접수는 기존 API에서 서버 검사를 적용한다.
- 응답을 잃은 요청은 PC가 연결된 상태에서 사용자가 같은 요청으로 다시 접수할 수 있다. 이미 접수돼 기기가 점유된 경우에도 같은 키로 영수증을 돌려받는다.

## 검증

- Python 관련 회귀 39개와 Node 웹 테스트 21개 통과. API 테스트는 접속 보고 없음, 만료, 격리, 실제 임대의 점유, 종료 임대의 정리 대기와 브라우저 세션의 저장 관찰 조회를 확인했다.
- 설치된 Chrome에서 실제 템플릿·스크립트와 ASGI 앱을 임시 SQLite로 검증했다. 키보드 준비 검사, 연결 만료·복구·조회 오류, 선택 유지와 재검사, 오프라인 초안 저장과 새로고침, 대상 종류 변경 시 이전 미리보기 초기화, 재실행 사유 유지, 자동 접수 0건을 확인했다. 접수 응답을 유실시킨 뒤 기기가 점유된 상태에서 같은 키를 재전송해 시범이 한 건만 저장된 것도 확인했다.

다음은 PC-04다. 실제 워커의 heartbeat 송신과 원격 실행, 독립 서버 배포는 이후 구현 및 수용 범위에 남아 있다.
