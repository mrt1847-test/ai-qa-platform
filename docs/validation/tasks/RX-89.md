- 소비한 선행: RX-79, RX-80, RX-86의 정식 preview와 승인 healing 해석.

## 제공 interface

묶음 실행 준비와 선택 정식 실행의 `healing_enabled` 체크박스는 기본 OFF다. `suite_execution.js`는 체크된 경우에만 `self_healing_enabled: true`를 preview와 접수에 보낸다. preview가 항목별 `healing_resolution`을 주면 키 고정 여부와 예산·episode·호출·시간 상한을 그 값으로 보여 준다. `HEALING_*` 차단이 있거나 `ready`가 아니면 접수 버튼을 열지 않는다.

입력이 바뀌면 준비 상태를 다시 확인한다. 접수 응답을 잃으면 같은 본문과 같은 idempotency key로 다시 확인한다. 시범 준비의 토글은 비활성이고 요청은 `self_healing_enabled: false`다. 수행 화면의 토글은 실행 중에 기존과 같이 비활성이다.

## 검증

```text
node --test tests/web/suite_execution.test.cjs
.venv/Scripts/python.exe -B -m pytest tests/integration/test_rx89_healing_prep.py -q -p no:cacheprovider --tb=short
```

UI **8 passed**. fixture **2 passed, 1.34s**. 같은 승인본에서 OFF preview는 healing resolution이 없고 모델 호출과 실행 접수가 0이다. ON preview는 서버가 준 키·상한을 반환하고, 키를 사용할 수 없으면 `HEALING_KEY_UNAVAILABLE`이며 ready가 아니다.

로컬 브라우저에서 묶음/선택 화면의 토글은 기본 OFF에서 켤 수 있고, 빈 구성과 승인 전 케이스는 준비 확인과 접수가 열리지 않았다. 시범 토글은 비활성이라 켜지지 않았다. 이 화면 확인은 복구 실행 성공이 아니다.
