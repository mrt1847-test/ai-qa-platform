# 프런트 샘플 확인 기록

2026-10-31 · localhost 정적 프런트의 **데스크톱 브라우저 수동 클릭 검사**입니다. 실제 AI/기기/DB 또는 제품 수용 시험 결과가 아닙니다.

사용자 미리보기 `127.0.0.1:8765`와 검사용 `localhost:8765`를 다른 브라우저 저장 origin으로 사용해 검증 조작을 분리했습니다.

확인한 동선:

- Web 선택 → 테스트 URL/브라우저 미리보기 → 장바구니 예시 → 모의 동작 2개 → 중단 저장 → 새로고침 후 AUT-072 v2/REC-024 보존. 미승인/미완성 상태 유지.
- AUT-041 v4의 출처 동작 5개 + 시범 동작 5개 사후 검토 → 승인 버튼 활성 → 승인 사유 저장 → 기본본 v2→v4 전환. SUITE-01은 여전히 v2/구성 v1, 과거 승인 v2 유효.
- SUITE-01에서 명시 갱신 → 구성 v2/케이스 v4 → FAIL + stop 정책 수행 → FAIL1/NOT_RUN2/총3.
- 실패 항목 분석 의견 추가 → 새 RUN에서 PASS로 재실행 → 전체 이력에 기존 FAIL 및 새 PASS가 별개 관측으로 표시. 최근 완료 보기는 조건별 projection으로 분모 감소.
- RUN-012 리포트: N10/PASS6/FAIL2/BLOCKED1/NOT_RUN1 → 완료100%, 검증 통과75%, 전체 대비 통과60%, 미검증2.
- Android 새 녹화 → 5개 모의 동작 → 녹화 완료/저장 → 미승인 새 버전 → 시범 PASS → 출처/시범 미검토 상태에서는 승인 버튼 비활성.
- 승인 v4에서 새 재녹화 → 1개 동작 후 중단 → 새 v6 미완성 저장, 기본 승인 v4 및 과거 승인 v2 유지.
- 데스크톱 개요/전후 화면·로그 검토 화면 스크린샷 확인. 검증 중 브라우저 error/warn 로그 없음.

문법 검사는 `node --check app.js`, `node --check demo-data.js`, `node --check serve.cjs`로 확인합니다. 정적 서버는 localhost GET/HEAD 파일 제공만 하며 mutation API가 없습니다.

화면마다 모든 버튼·브라우저 조합·좁은 화면 breakpoint·장기 저장/용량 한계·멀티 탭 경합을 포괄 검증한 것은 아닙니다. 미리보기 서버 재실행은 [README](README.md)를 따릅니다.
