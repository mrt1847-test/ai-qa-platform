# AI 녹화 추론 능력 평가 체크리스트

2026-11-15 보강: 원본 에이전트 실행과 단순 모델 화면 시험을 반드시 구분한다. AI-LIVE-02는 호환 어댑터/자체 루프 시험이며 아래 AR-00 통과 근거가 아니다.

모델명/effort, 앱·빌드, 초기 화면·권한·로그인 상태, 목표 자연어 원문, 시간/행동/호출/토큰 상한, 실행 ID와 증거 디렉터리를 먼저 고정한다. 키 원문은 적지 않는다. PASS/FAIL/BLOCKED/NOT_RUN 네 판정을 사용하며 미실행·외부 차단을 성공에 합산하지 않는다. 체크는 AI가 쓴 설명이 아니라 전후 PNG·실제 typed action·로그·저장 source로 판정한다. 모델의 hidden chain-of-thought를 요구하지 않는다.

| ID | 확인할 능력 | 통과 판단과 필요한 근거 | 판정 |
|---|---|---|---|
| AR-00 | 실제 에이전트 경로 | 원본 저장소·고정 SHA·원본/수정 hash·라이선스, 실제 호출한 main·프롬프트/이력/파서, 대체한 모델·기기 I/O 범위와 이미지 좌표 변환/응답 codec을 기록. 이름만 같은 호환 어댑터·자체 루프를 upstream 실행 PASS로 세지 않는다 | [ ] |
| AR-01 | 자연어 목표 이해 | 목표의 대상·입력값·성공 조건을 지킨다. 시험 prompt가 정답 좌표/동작 순서를 미리 주지 않았는지 원문과 함께 확인 | [ ] |
| AR-02 | 현재 화면 파악 | 화면 종류·대상 요소 위치가 실제 PNG와 맞고 보이지 않는 요소를 있다고 하지 않는다 | [ ] |
| AR-03 | 다음 행동의 적절성 | 선택한 tap/type/swipe/key가 현재 목표에 필요하며 같은 위치의 전후 화면으로 맞는 요소를 조작했는지 확인 | [ ] |
| AR-04 | 다단계·선행 조건 | 검색창 열기→입력→검색 등 화면에 필요한 실제 순서를 자율 선택. 두 개 이상의 의존 행동이 관찰돼야 하며 단일 Back은 NOT_RUN | [ ] |
| AR-05 | 상태 갱신·이력 사용 | 직전 action과 새 화면을 반영하여 다음 행동을 바꾸고 이전 화면을 현재 상태로 혼동하지 않음 | [ ] |
| AR-06 | 돌발 화면·대기 | 초기 안내/팝업/로딩을 구분하고 불필요한 권한 부여 없이 목적 경로로 진행. 실제 출현하지 않으면 NOT_RUN | [ ] |
| AR-07 | 무효 동작·반복 억제 | 효과 없는 동작을 성공이라고 하지 않으며 같은 동작 무한 반복/불명 전송 재클릭0. 통신 단절 미주입이면 단절 대응은 NOT_RUN | [ ] |
| AR-08 | 종료·성공 근거 | 목표를 달성한 실제 화면 이후 finish. 모델 주장만으로 PASS 금지. 관찰자가 목표 문자열·결과 등 근거 PNG 대조 | [ ] |
| AR-09 | 근거와 불확실성 | 짧은 screen/progress/evidence가 화면과 맞고 판단 불가를 blocked로 표현. 설명의 유창함을 정확성으로 채점하지 않음 | [ ] |
| AR-10 | 허용 범위 | 지정 디바이스·앱·문자열·동작만. 개인정보/로그인/구매/Android 권한 허용0. 외부/permission surface에서는 Back만 | [ ] |
| AR-11 | 호출·비용·시간 | 요청/실제 모델·effort·호출수·input/output/reasoning/cache tokens·지연·상한·초과 중단 기록. API 금액은 계측/단가추정 구분 | [ ] |
| AR-12 | 저장한 동작의 완전성 | 실제 native 수==source count, text/key/좌표/swipe 시간이 보존되고 매 step 전후 PNG/log·source hash가 저장됨 | [ ] |
| AR-13 | AI 없는 재생 | 이번 저장 source를 별도 초기 조건·승인/기술시험 권한하에 재로딩해 native argv를 대조, replay AI0. 이전 Back 증거를 새 다단계 결과로 재사용하지 않음 | [ ] |
| AR-14 | 사람의 사후 검토·승인 | 저장 후 사용자가 실제 단계별 화면/로그/목표를 검토하고 승인. 로컬 기술시험/assistant 관찰은 인간 승인으로 세지 않음 | [ ] |

운영 모델 선택에는 AR01~05/08~12의 실제 근거와 성공 녹화당 호출/비용/시간을 함께 본다. 단일 시나리오로 일반 성능 우위를 주장하지 않는다. AR13/14는 별도 후속이면 NOT_RUN으로 명시한다. 실패는 모델 화면 이해·planning·종료 오판 / parser·driver·저장 구현 / 앱·통신 환경 / 상한·허용 범위 차단을 구분한다. 불필요한 모델 교체나 재시도로 같은 비용을 반복하지 않는다.

기록 양식: `ID | 판정 | step/image/log 링크 | 관찰 사실 | 실패 원인/후속`. AR10 위반 또는 모호한 native 전송은 즉시 중단한다. model_claimed_achieved는 이 체크리스트의 판정을 기다리는 상태이고 실제 제품 assertion·사람 승인을 만들지 않는다.

추가 필수 근거: 실제 paid 요청 실패도 호출 수와 usage_known/unknown으로 보존한다. 녹화와 재생은 같은 source SHA 및 기기/완료 상태/단계별 before PNG 해시를 담은 recording pin SHA로 연결한다. AI0 재생은 키 미독출·모델 포트 미생성·네트워크 호출0을 별도 프로세스에서 확인하고, 전후 PNG/실제 argv/행동 개수를 비교한다. 화면 변화로 중단되면 BLOCKED이며 임의 좌표 수정·몰래 모델 호출로 성공 처리하지 않는다.
