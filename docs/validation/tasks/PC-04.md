# PC-04 · 등록 실행 PC와 독립 서버 후속 설계

2026-11-03 (Asia/Seoul) · `source_audit_design` · [작업 카드](../../superpowers/plans/2026-11-02-managed-pc-transition.md#pc-04)

## 산출물과 인계

- [구현 경계](../../managed-pc/RUNTIME_BOUNDARIES.md)에 현재 launcher·worker·lease·증거·인증·비밀 경계를 함수 단위로 대조했다. 고정 Mobile-Agent와 CUAWright의 authoring 연결점, 재사용 범위, 임의 코드 실행의 신뢰 경계를 기록했다.
- [RX 색인](../../managed-pc/IMPLEMENTATION_TASKS.json)에 31개 카드의 직접 선행·환경·검증 등급·완료 인계를 등록했다. 각 카드에는 대상 파일, 제공 인터페이스, 부정 사례와 검증 명령이 있다.
- AD-01의 실기기 관찰은 재사용한다. AD-02~04와 W01-02/W29-05는 기존 상태를 보존하고 새 카드가 수용할 범위를 매핑했다. CF-01은 선택 범위다.
- [다음 작업 RX-01](../../managed-pc/WORKER_TASKS.md#rx-01)은 `acknowledge_attempt` 및 `reconcile_jobs`의 서버 부팅 ID를 원격 worker attempt와 분리한다. `WorkerIncarnation(worker_id, session_id, boot_id)`의 저장 및 검증 계약과 migration이 다음 claim 카드의 입력이다. [PC-02](PC-02.md)의 서버 수신 heartbeat와 기존 legacy attempt를 보존한다.

## 검증과 남은 조건

- Python으로 W/AD·UX/PC/RX 색인의 JSON, ID 유일성, 선행 경로와 순환 여부, RX 카드·앵커·인계 경로 및 Current 준비 상태를 검사했다. 기존 W 126/163과 AD/UX 1/7을 보존했다. `git -c core.safecrlf=false diff --check`와 새 문서 공백 검사도 수행했다.
- 이번 증거 등급은 소스 조사·설계다. 실제 원격 worker 소비, 독립 호스트 배포, Android/Web 통합, 전원 종료 중 검토·승인, 재연결과 두 worker 경합은 해당 RX 실환경 증거가 남아 있다. Windows 관리 호스트·SQLite·OIDC는 첫 운영 검증 후보이며 실제 호스트, DNS, IdP, VM 및 운영 키는 아직 확정되지 않았다.
