# Android 웹 영상 연동

사용자가 웹에서 자연어 자동화를 시작하고 실제 에뮬레이터 화면이 움직이는 것을 보며, 저장 동작을 재생하고 실시간 화면을 웹에서 볼 수 있게 한다. 제품 내 영상 저장·다운로드 기능은 추가하지 않는다. README는 이 구현의 실제 사용자 흐름을 새 영상으로 촬영한다. 사용자는 영상 연동까지 구현하는 범위를 선택했고 이어서 진행하도록 요청했다.

## 선택한 구현 방향

구현자는 기존 서버–워커 구조와 브라우저 기본 video 재생을 유지하는 방향으로 결정한다. Android `screenrecord`의 연속 H.264 출력을 워커의 FFmpeg가 fragmented MP4로 포장하고, 인증된 관리 API가 메모리에서 중계한다. 웹의 MediaSource video 플레이어가 이를 재생한다. 서버는 ADB를 실행하지 않는다. 워커는 기존 작업 실행과 별도 스레드에서 영상 수요를 처리하므로 모델 대기·재생 중에도 영상이 이어진다.

스크린샷 반복 전송은 요구한 동작 영상에 맞지 않아 제외했다. WebRTC는 추가 시그널링·서버 실행물 배포가 필요하고, 직접 WebCodecs 방식은 H.264 access unit 처리와 디코더 수명 관리를 별도로 구현해야 하므로 이번에는 채택하지 않는다. FFmpeg는 선택 설치 항목으로 제공하고 없으면 지원 불가 사유를 표시한다.

## 사용자 흐름

- Android 기기를 선택하면 웹의 영상 패널에서 **실시간 화면 보기**를 누른다. 화면이 그대로 표시되며, 이 작업은 탭·입력·모델 호출을 실행하지 않는다.
- 기존 AI 녹화·시범 재생을 사용한다. 같은 프로젝트·기기의 영상 세션은 페이지 이동에도 유지하고 다음 페이지에서 다시 연결한다.
- **연결 종료** 또는 마지막 화면의 갱신 중단으로 캡처를 종료하고 영상 버퍼를 즉시 비운다. 저장·다운로드·녹화 버튼은 제공하지 않는다.
- 대기·연결 중·실시간·중단·지원 불가를 구분한다. 오래된 프레임을 실시간이라고 표시하지 않는다. 화면 맞춤은 세로 비율을 보존한다.

## 경계와 제한

기존 브라우저 세션·CSRF와 프로젝트 범위, 워커 인증 및 물리 기기 소유를 그대로 확인한다. 영상은 QA 증거·승인·모델 입력과 분리한다. 비밀 참조가 있는 활성 작업에는 영상 전송을 허용하지 않으며, 작업 실행부와 중계부에서 차단한다. 조회 권한 없는 사용자에게 세션 존재나 영상 바이트를 공개하지 않는다.

영상은 디스크에 자동 보관하지 않는다. 연결당 최대 10분, 앱당 동시 3개로 제한한다. 메모리에는 최신 keyframe부터의 짧은 재생 버퍼만 최대 16MiB 유지한다. 새 keyframe이 오면 이전 구간을 폐기한다. 연결 갱신이 20초 끊기면 캡처를 종료하고 픽셀 버퍼를 즉시 비운다. MP4 초기화와 조각의 순서·크기·중복을 검사한다. 다른 생산자가 기존 세션에 영상을 섞을 수 없다. 재시작 시 이전 세션은 종료된다.

## 완료 근거

세션 인증·만료·용량·중복·잘못된 조각, 워커 프로세스 종료·장치 오류, 브라우저 연결 복구·실시간 재생과 저장 API 부재를 테스트한다. 실제 Android 영상으로 웹 플레이어의 시간과 프레임이 진행되고, 같은 웹 화면에서 녹화와 재생을 관찰한다. README 파일은 연속 영상으로 생성하고 원본·실행 ID·편집 범위·QA 결과를 기록한다.

## 사용자 범위 정정

사용자는 2026-11-18에 제품에서 필요한 것은 실시간 화면 보기뿐이며 영상 저장 기능을 요청하지 않았다고 명확히 했다. 앞선 저장 기능 제안은 구현자가 임의로 확장한 것이며 제거한다. README용 외부 촬영과 제품 기능을 혼동하지 않는다.
