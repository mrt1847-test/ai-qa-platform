# RX-88 · Web replay의 승인 정책 소비

- 상태: complete (core_contract). 부모 revision 18f2328. 이 파일을 포함한 커밋이 완료 revision이다.
- 적용 계약: C00/C01/C04/C05/C08/C09/C14. DB migration 없음. 새 화면 없음.
- 소비한 선행: RX-86, RX-94, RX-95, RX-96, RX-54, RX-61의 로컬 Web package replay.

## 제공 interface

`WebReplayHandler.handle`는 claim snapshot의 healing pin과 replay limits를 재생 전에 읽는다. pin이 잘못되면 `replay_pin_invalid`이다. trial은 healing을 끈다. regression에서 pin이 켜져 있고 `WebReplayContext.healing_client`가 없으면 `healing_runtime_unavailable`이며 브라우저 동작은 0이다.

claim `limits.max_actions`보다 allowlisted step이 많으면 `action_budget`으로 거절한다. `healing_client.lookup`이 `target_not_found` 또는 `layout_shift`를 반환하고 현재 관찰이 같은 대상을 유일하게 증명할 때만 원래 allowlisted step을 한 번 실행한다. assertion 실패, 다른 action/path, 예약 소진, 취소는 실행하지 않는다. `dispatch_started` 이후의 거절은 unknown이며 다시 클릭하지 않는다. actor AI 호출은 0이고 package digest는 유지한다.
