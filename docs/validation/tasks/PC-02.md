# PC-02 · 서버 시각 기반 실행 PC 연결

2026-11-03 (Asia/Seoul) · core_contract · [구현 카드](../../superpowers/plans/2026-11-02-managed-pc-transition.md#pc-02)

워커가 자신의 등록 토큰으로 `POST /api/v1/worker/heartbeats`에 `boot_id`를 보낸다. 서버는 토큰에서 워커·프로젝트·목적을 확인하고 서버 UTC 시각을 저장한다. 응답의 `heartbeat_seconds`는 10, `offline_after_seconds`는 45다. 기존 등록은 실제 보고 전까지 unknown이다. 토큰 폐기 시 해당 연결 기록이 사라진다. 기기 관찰 시각은 연결 판정에 쓰지 않는다.

기기 작업은 접수 시 연결 세대를 저장하고 배정 시 현재 세대와 기기 소유권을 확인한다. 시범·정식·재실행은 저장된 `limits.resource_id`를 사용한다. 45초 단절 후 복귀하거나 부팅이 바뀌면 새 세대가 생긴다. 이전 부팅의 지연 보고는 거부한다. 새 세대에서 이전 대기 작업을 자동 배정하지 않는다. 기존 대기 기록은 남아 있어 취소할 수 있으며 새 작업은 사용자가 접수한다. 현재 세대를 잃은 관리 대상 작업은 임대 확인·연장과 동작 직전 검사에서 차단한다.

**구현 결정.** SQLite 0037의 삽입 트리거로 새 기기 작업의 세대를 같은 트랜잭션에서 고정했다. 공통 큐와 직접 삽입하는 실행 경로 모두 적용된다. 기존 대기 작업에 연결 세대를 소급 부여하지 않았다. 이미 저장된 녹화 조회·검토·승인은 기존 서버 근거를 사용한다.

## 검증 범위

- 임시 SQLite 업그레이드, 등록 보존, 인증되지 않은 프로젝트·워커·목적 및 폐기된 토큰 거부.
- 고정 시각 44.999초/45초 경계와 미래 관찰 시각 무시. 같은 부팅의 복귀, 새 부팅, 이전 부팅 보고의 지연 도착, 이전 세대의 배정·임대 연장·동작 차단.
- 실제 API로 접수된 시범과 저장 스냅샷을 복제한 재실행의 기기 배정. 기존 승인·접수 영수증 회귀 검사.

PC-02와 관련 실행·승인 회귀 63개 통과. 오프라인 진단 거절/복구와 복구 제안 재녹화 2개 별도 통과. 광범위 실행에서 나온 두 관련 fixture 실패는 연결 보고를 추가하고 재검증했다. 그 실행에는 기존 overview 경로를 금지하는 W10-03 기대값과 현재 Python 실행 환경의 설치·하위 프로세스 시작 관련 6개 실패도 있었다. 실제 Hyper-V 검증 W01-02는 별도 환경 gate로 제외했다.

PC-03은 연결 상태와 조회/실행 버튼을 화면에 반영한다. PC-04 이후에는 등록 PC의 실제 heartbeat 송신 루프, 원격 소비, 독립 서버 배포와 전원 종료 통합 검증이 필요하다.
