# 현재 구현의 사용자 관점 UI 검토

검토일: 2026-11-01 (Asia/Seoul). 기준 HEAD: `5ff4e5273bbfc5ae0283690bf91dbb2918f6c9bb`와 작업 트리의 기존 변경. 검토 중 큐 문서는 완료80/163, Current W18-02로 갱신되어 있었다. 이 보고서는 해당 진행 상태를 변경하지 않는다.

**현재 화면은 데이터·계약 확인에는 쓸 수 있지만, 일반 사용자가 녹화 준비부터 저장까지 화면만 보고 끝내기에는 부족하다. 우선순위는 핵심 동선 연결 → 저장·입력 보호 → 편집 구조 → 목록·시각 정리다.**

실제 제품 라우트를 브라우저로 조작했다. `prototype/`의 모의 화면은 평가 근거에서 제외했다. 분리된 임시 DB에 프로젝트2개·케이스32개·오프라인 자원2개를 준비했고, 실제 기기·AI·설치·배포·사용자 런타임은 사용하지 않았다. 1440×1000, 1024×768에서 확인했다. 이는 전문가의 작업 흐름 검토이며, 독립 사용자의 수용 시험이나 실제 녹화·실행 성공 검증은 아니다.

원본 기준: [UI_SPEC](../../../UI_SPEC.md)의 공통 정보 구조·미저장 편집 규칙, UI-03/04/05/07/09. [소스 비교 결과](ui-2026-11-01/verification.json)에서 검토 시작·종료의 `src/` 153개 파일 hash 차이는0이었다. 제품 코드는 수정하지 않았다.

**수정 계획 추가:** [사용자 작업 흐름을 완성하는 개선 계획](../../superpowers/plans/2026-11-01-ui-ux-improvements.md)에 각 이슈의 개선 후 사용자 흐름·작업 단위·파일/API 경계·오류/복구·완료 증거를 연결했다. 녹화·저장/탐색·편집/목록·설정·접근성의3개 상세 문서로 분리했다. 문구·스타일만 고치는 계획이 아니라 작성→저장→재사용·복구가 가능한 흐름으로 보완한다. 구현은 아직 하지 않았다.

계획 추가 시 W18-02~05/W19-01~02 코드·인계가 존재했고 Current는 W19-03이었다. 아래 관찰과 캡처는 최초 검토 시점의 사실로 유지하며, 이후 viewer/승인 구현은 계획에서 재사용 대상으로 반영했다. 그 추가 구현을 이번 문서 작업만으로 브라우저 수용했다고 판단하지 않는다.

### UX-01 — 실제 녹화 준비 흐름으로 진입점 통일

재현: 프로젝트 개요 → 새 녹화. `/recordings/new`는 ‘기기를 고릅니다’라고 안내하지만 고르는 제어가 없다. 소스로 확인한 별도 `/recordings/wizard`에 직접 진입하면 자원은 문단으로 나오고, 주소·패키지·자연어도 문단이다. Web/Android 링크는 표시 항목을 바꾸지만 입력할 수 없다. ‘다음’은 항상3단계, ‘이전’은 항상1단계다.

근거: [진입 화면](ui-2026-11-01/01-recording-entry-1440.png), [wizard](ui-2026-11-01/02-recording-wizard-1440.png), `src/aiqa/api/catalog.py:94`, `src/aiqa/web/templates/recording_setup.html`. 관련 완료 범위 W16-01/03.

개선: 모든 ‘새 녹화’를 하나의 준비 화면으로 연결한다. ①기기 카드 선택 ②Web URL 또는 Android 앱·빌드·계정 등 설정 ③자연어 검증·기대 결과를 입력한다. 각 단계의 선택을 보존하고 뒤로 가기·초안 저장을 제공한다. 오프라인이면 연결 방법과 시작 차단 사유를 보여 주되 초안 입력·저장은 가능하게 한다. 실제 native 실행 준비 전에는 시작을 활성화하지 않는다.

완료 판정: TC 없이 Web/Android 초안을 각각 UI에서 생성·재조회할 수 있고, 대상 전환 시 공통 입력은 유지되며 대상 전용 입력은 계약대로 처리된다. 기기 이름·선택 상태·차단 사유가 보인다. ‘화면 방문이 native 호출0’이라는 기존 검증은 유지한다.

### UX-02 — 환경·데이터 저장을 실제 API 계약에 연결

재현: 환경 편집에서 이름 수정 → 환경 저장. 데이터 화면에서 이름·행 ID·값 입력 → 데이터 저장. 두 경로 모두 `Idempotency-Key is required` 오류 본문만 있는 페이지로 이동했다. 이는 API 저장 기능 전체가 없다는 주장이 아니라, 제공된 HTML form으로 작업을 끝낼 수 없다는 문제다.

근거: [환경 오류](ui-2026-11-01/09-environment-submit-error.png), [데이터 오류](ui-2026-11-01/10-dataset-submit-error.png), `src/aiqa/web/templates/environment_editor.html:6`, `src/aiqa/web/templates/datasets.html:19`. form은 API로 기본 form POST를 보내지만 필요한 JSON·인증/CSRF·멱등 처리와 화면 응답 처리가 연결되지 않았다. 관련 W11-02, W12-01.

개선: 기존 공통 요청 도구를 통해 계약에 맞게 제출한다. 저장 중 중복 제출을 막고 성공 시 저장 버전·후속 동작을 표시한다. 실패 시 현재 화면과 입력을 유지하고 필드별 오류·재시도 방법을 안내한다. Web 선택 시 Android 입력을 숨기고, 종류·방향·열 타입은 선택형으로 제공한다. 데이터는 행/열 표 편집과 케이스 선택기를 사용하고 UUID 직접 입력을 요구하지 않는다.

완료 판정: 실제 버튼으로 저장→재조회가 성공한다. 잘못된 URL/숫자/열 값은 해당 필드 옆에 표시되고 입력이 유지된다. 뒤로 가기를 오류 복구 수단으로 요구하지 않는다. 저장 실패 후 같은 요청을 재시도해도 중복 revision을 만들지 않는다.

### UX-03 — 입력 변경 감지와 이동 취소

재현: 로그인 케이스의 검증 정의 → 목적을 ‘저장하지 않은 임시 변경 UX 확인’으로 변경 → 단계 탭 → 검증 탭. 경고 없이 이동하고 목적이 ‘주문 정보 표시 검증’으로 돌아왔다. body의 `data-dirty`는 `false`였다.

근거: [이동 직후 화면](ui-2026-11-01/06-unsaved-after-tab-1440.png), `src/aiqa/web/static/navigation.js:24`, `src/aiqa/web/static/definition_editor.js`. 현재 guard는 서버가 처음부터 dirty로 렌더한 경우만 붙고 실제 입력 변경을 감지하지 않는다. 숨겨진 안내 패널도 저장/버리기/취소와 목적지 보존을 제공하지 않는다.

개선/완료 판정: 입력 변경 후 탭·목록·프로젝트 이동은 ‘저장 후 이동 / 버리고 이동 / 계속 편집’을 제공한다. 취소하면 입력·초점·위치를 유지한다. 저장 성공 후에는 불필요한 경고가 없어야 한다. 비밀 원문을 브라우저 저장소에 넣는 자동 복구는 추가하지 않는다. UI_SPEC 공통 미저장 규칙과 맞춘다.

### UX-04·06 — 프로젝트 맥락과 탐색 복구

재현: 검증 정의의 상단 검색에 ‘로그인’ 입력 → 검색. 현재 케이스 검색 결과가 아닌 `/ui/shell?filter=...`의 ‘목록 / 항목 1’이 표시됐다. ‘현재 프로젝트’는 케이스 화면에서는 케이스 목록, 설정에서는 프로젝트 목록으로 이동한다. 프로젝트명은 상단에 표시되지 않는다.

근거: [검색 도착 화면](ui-2026-11-01/07-header-search-1440.png), [케이스 상세](ui-2026-11-01/04-definition-1440.png), `src/aiqa/web/templates/base.html`, `src/aiqa/web/routes.py`.

개선: 프로젝트명과 전환 제어, 개요/케이스/묶음/수행/리포트/환경/설정 메뉴, 현재 페이지 breadcrumb를 일관되게 제공한다. 미구현 메뉴는 준비 중임을 명시한다. 검색을 현재 프로젝트 범위로 구현하거나 실제 동작 가능한 페이지 검색만 남긴다. 샘플 shell을 실제 검색 목적지로 쓰지 않는다. 케이스명을 제목으로 쓰고 검증 내용·녹화 기록·시범·검토 상태를 한 작업 공간에 둔다. TC는 선택 참조 영역에 둔다.

완료 판정: 어느 페이지에서도 프로젝트명을 확인하고 케이스·환경·설정으로 이동할 수 있다. 검색 결과는 같은 프로젝트의 실제 항목이며0건 상태와 범위를 표시한다. 현재와 다른 의미의 링크에 동일한 ‘목록/상세’를 반복하지 않는다.

추가 소스 관찰: `navigation.js:10`은 모든 경로의 스크롤을 하나의 `aiqa.scroll`에 저장한다. 다른 페이지에 이전 위치가 적용될 수 있다. 실제 다양한 브라우저 이력 복귀 시나리오는 이번에 검증하지 않았으므로 재현 결함 수에 포함하지 않는다. 수정 시 목록 URL/필터별 복귀 위치와 새 상세 화면의 시작 위치를 구분해 확인한다.

### UX-05·08 — 검증 편집을 사람이 읽는 구조로 변경

근거: [1440 편집](ui-2026-11-01/05-definition-editor-1440.png), [1024 편집](ui-2026-11-01/12-definition-editor-1024.png), `src/aiqa/web/templates/case_definition.html:3`. 자연어도2줄이며 사전조건·단계·경로는 JSON·Unicode escape로 표시된다. 1024에서 textarea7개 모두 약161×36px로 측정됐다. 가로 스크롤 초과는 관찰되지 않았으므로 ‘화면이 넘친다’는 결함은 주장하지 않는다.

개선: 자연어를 넓은 주 입력 영역으로 두고 목적/사전조건, 변수 표, 수행 단계 카드, 단계별 검증, 최종 기대, 필수·금지 경로를 읽을 수 있는 한글로 편집한다. 복잡한 옵션과 원본 JSON은 고급 영역으로 접는다. 자연어에서 구조화하는 AI 제안 기능은 W16-02 미구현 범위와 연결하고 현재 기능인 것처럼 표시하지 않는다. 1440은 본문+상태 요약 패널, 1024는 단일 본문+접을 수 있는 보조 패널을 권장한다.

완료 판정: 사용자가 JSON 문법을 몰라도 단계 추가·검증 수정·변수 변경·저장을 할 수 있다. 전체 검증 문장과 저장 버튼을 읽을 수 있다. JSON 해석 실패를 포괄 문구로만 알리지 않는다. 편집하지 않은 snapshot 필드는 보존한다.

### UX-07 — 3,000개 회귀 업무에 맞는 목록

근거: [1440 목록](ui-2026-11-01/03-cases-1440.png), [1024 목록](ui-2026-11-01/13-cases-1024.png), [2페이지](ui-2026-11-01/14-cases-page2-1024.png). 이번 검토 데이터는32개로, 3,000개 성능 시험을 한 것은 아니다. 첫 페이지25개 뒤 ‘다음’만 있고 마지막7개 페이지에는 이전·총건수·현재 범위 안내가 없다. 선택0개에서도 일괄 행동이 노출된다. 전체 UUID 열이 이름과 동일한 비중을 차지하고 대상·최신 결과는 없다.

개선: 짧은 표시 ID+케이스명 중심으로 대상(Web/Android), 현재 초안/승인 버전, 최근 결과/시각, 검토 필요 여부를 보여 준다. 전체 UUID는 상세/복사에 둔다. 현재 필터·검색 건수·페이지 범위·이전/다음·선택 건수를 표시한다. 선택0개에서는 일괄 행동을 비활성화하고 이유를 제공한다. 상태는 ‘가능’ 대신 ‘정식 실행 가능’, ‘검토’ 대신 ‘검토 대기’ 등으로 의미를 명확히 한다. 플랫폼/결과/태그 필터와 저장 보기의 지원 범위는 백엔드 계약을 확인한 뒤 편성한다.

완료 판정: 32개 데이터에서 두 페이지 왕복·검색·선택 유지와 범위를 확인한다. 이후 대표3,000개 데이터로 목록 응답·검색·선택 범위·배치 한도를 별도 검증한다. 초안·기록 저장·시범 통과·사람 승인·최근 실행 결과는 서로 다른 상태로 표시한다.

### UX-09 — 연결 상태를 행동 안내로 바꾸기

근거: [오프라인 자원](ui-2026-11-01/15-resources-offline-1024.png), `src/aiqa/web/templates/environments.html`, `components/device_preview.html`. ‘오프라인 / 사용할 수 없음’ 옆에도 활성 ‘이 기기로 녹화’가 있고 선택 자원 ID 없이 같은 주소로 이동한다. 상단 ‘이 PC: 연결됨’과 자원 오프라인의 차이를 설명하지 않는다. 진단 문구는 VM/IPC/proof/lease 등 구현 용어 중심이다.

개선/완료 판정: PC 중계 연결·테스트 브라우저/Android 연결·실행 가능 상태를 구분한다. 선택 자원을 준비 화면에 유지하고, 현재 실행이 불가능하면 ‘이 기기로 초안 준비’ 등 실제 가능한 행동으로 명명한다. Android는 USB 연결/ADB 권한, Web은 실행 환경 준비 등 다음 조치를 안내한다. 최근 캡처는 관찰 시각·오래됨 여부와 함께 표시하고 실제 스트리밍/수동 제어처럼 오해시키지 않는다. 실시간 화면·원격 제어는 이번 검토에서 검증하지 않았다.

### UX-10 — AI 역할·키·비용·healing 정책의 명확화

근거: [설정 화면](ui-2026-11-01/16-project-settings-1024.png), `src/aiqa/web/templates/settings.html:13`. 역할이 authoring/verification/healing/maintenance로 노출되고 실패 정책·보관·healing 범위를 문자열로 입력한다. 키 필드4개는 DOM에서 `type=text`였다. 실제 키를 입력하거나 외부 요청을 보내지 않았다.

개선: ‘녹화 AI / 검증 AI / 예외 복구 AI / 유지보수 AI’로 설명하고 기본 재생은 AI 동작 호출 없이 수행한다는 정책을 표시한다. 셀프힐링은 기본OFF, ON 가능 범위와 추가 호출/비용 한도를 명시한다. 자유 문자열 대신 허용된 정책을 선택하게 한다. 키는 기본 마스킹하고 연결 있음/없음·교체·해제의 의미를 명확히 한다. 모델 확인이 유료 API 호출을 발생시키면 실행 전에 표시한다. 전역/프로젝트/케이스의 유효 설정값과 상속 출처도 보여 준다.

완료 판정: 사용자가 어떤 상황에서 AI 비용이 생기는지, healing이 현재 OFF인지, 설정 저장이 기존 바인딩을 유지/교체/해제하는지 이해할 수 있다. 키를 응답·로그·브라우저 저장소에 노출하지 않는 기존 계약은 유지한다. 오류 시 ‘입력은 그대로’라고 하면서 실제로 지운 키를 그대로 보존했다고 오해시키지 않는다.

### UX-11 — 이름·초점·오류 전달

근거: 1024 목록 DOM 검사에서 checkbox25개 모두 label/aria-label이 없었고, 공통 검색은 접근 가능한 이름이 없었다. 구체적인 스크린리더 사용 시험은 하지 않았다.

개선/완료 판정: 행 선택에 ‘로그인 후 주문 내역 조회 선택’처럼 대상을 포함한 이름을 붙이고 검색 범위를 label로 알린다. 활성 메뉴·탭과 초점을 구별한다. 필드 오류는 해당 입력과 연결하고 저장 상태는 status로 알린다. 키보드만으로 검색→선택→상세→편집→오류 수정→저장을 수행하며 1440/1024에서 가려지는 필수 행동이 없는지 확인한다.

## 앞으로 구현할 화면에서 지켜야 할 사용자 흐름

다음은 최초 검토 당시 후속 범위로 남긴 권장 수용 기준이며, 당시 완료된 기능의 결함으로 세지 않았다. 계획 추가 시점에 구현된 W18/W19 코드는 [N03](../../superpowers/plans/ui-ux-2026-11-01/02-navigation-and-editing.md#ux-06)과 [V02](../../superpowers/plans/ui-ux-2026-11-01/03-management-and-accessibility.md#ux-08)에서 재사용·연결·수용한다. 실제 native 경로의 환경 대기는 별도로 유지한다.

- **완료 후 검토:** 상단에 케이스·정확한 버전·녹화 종료/저장 상태를, 왼쪽에 탭·스와이프 등 단계 목록을, 중앙에 전후 캡처를, 옆에 해당 동작/시간/로그/검증 내용을 둔다. 미검토 단계로 이동하고 증거 누락을 구별한다. 사람은 저장된 기록을 확인한 뒤 승인/반려한다. 녹화 도중 승인을 요구하지 않는다.
- **재녹화:** ‘새 녹화 초안 생성’과 ‘기존 승인본 유지’를 명시한다. 이전/새 기록·검증 내용의 차이와 미완성 종료 사유를 비교하고, 재녹화만으로 정식 승인본이 바뀌었다고 표시하지 않는다.
- **시범 실행 준비:** 현재 화면은 목적·환경·검사·확인을 설명하는 문단뿐이다([관찰](ui-2026-11-01/11-trial-setup-1440.png)). 실제 버전·환경·데이터·대상과 사전 검사 결과를 선택/조회할 수 있게 한다. package가 없으면 ‘재생 절차가 아직 생성되지 않음’과 다음 행동을 표시한다. 승인 없는 시범과 승인본 정식 실행을 구분하고 시범 healing OFF를 유지한다. W17-01 core API 확인과 실제 브라우저/native 실행 성공을 혼동하지 않는다.
- **결과 누적:** 실행마다 사용한 버전·환경·데이터·결과·근거로 돌아갈 수 있게 하고 최초 실패를 재시도 성공으로 가리지 않는다. 케이스 최근 결과 요약과 변경 불가능한 과거 기록을 연결한다.

## 권장 보완 순서와 작업 단위

이 표는 최초 검토의 보완 제안이다. 추가한 [상세 계획의 실행 순서·의존 관계](../../superpowers/plans/2026-11-01-ui-ux-improvements.md#실행-순서와-차단-처리)가 이를 구체화한다. NEXT_ACTION의 실행 순서를 임의로 바꾸거나 기존 완료 항목을 되돌린 것은 아니다.

| 순서 | 제안 단위 | 완료 증거 |
|---|---|---|
| 1 | 새 녹화 진입점 통일·기기 선택 상태 전달 | 개요/목록/자원에서 동일 준비 화면 도달, 선택 자원 유지 |
| 2 | 환경 저장 UI 연결·필드 오류 | 버튼으로 저장/재조회, 잘못된 값 수정 후 성공 |
| 3 | 데이터 저장 UI 연결·행 편집 | 표 입력→저장→재조회, 행 오류와 입력 유지 |
| 4 | 검증 편집 dirty 감지·이동 보호 | 탭/목록/프로젝트별 저장·버리기·취소 |
| 5 | 공통 검색 목적지·프로젝트 메뉴 | 실제 프로젝트 검색,0건, 전환·복귀 |
| 6 | 녹화 wizard Web 입력·초안 저장 | TC 없이 URL/기대 내용 저장·왕복 |
| 7 | 녹화 wizard Android 입력·전환 | 앱/빌드/계정 선택·전환 보존·오프라인 안내 |
| 8 | 검증 정의의 단계/기대 편집 | JSON 없이 편집·저장, snapshot 보존 |
| 9 | 목록 상태·페이지·선택·행 이름 | 32개 왕복과 키보드 선택, 이후3,000개 별도 시험 |
| 10 | 모델·healing 설정 제어와 키 마스킹 | 유효값·상속·추가 호출 안내, 실제 키 없는 UI 확인 |
| 11 | 공통 시각 계층·1440/1024 수용 | 같은 대표 데이터로 전체 페이지 before/after·키보드 확인 |

W18 사후 검토 viewer 작업은 위 보완의 준비 여부와 의존 관계를 확인해 병행할 수 있다. 전체 페이지를 한 번에 재작성하는 작업으로 합치지 않는다.

## 검증 방식에 대한 보완

현재 일부 W11/W16 시험은 API를 직접 호출하고 HTML에 안내 문구가 있는지 확인한다. 예를 들어 `tests/integration/test_w16.py`의 wizard 시험은 API 저장과 표시 내용, `<button` 부재를 확인한다. 이것은 화면 방문 시 무단 실행이 없음을 확인하는 데 도움이 되지만 사용자가 화면에서 입력·저장할 수 있음을 증명하지 않는다. ‘API core 완료’와 ‘사용자가 화면으로 완료’를 구분해 인계해야 한다.

각 UI 보완은 화면의 실제 제어를 통해 정상 저장·오류·취소·복귀를 확인한다. native 호출0 검증을 유지하면서 필요한 편집 제어를 제공한다. 기능 시험 성공만으로 시각·사용성 수용을 완료 처리하지 않는다. 이번 검토는 전체 회귀 시험을 재실행하지 않았고 이전141개 통과 결과를 현재 작업 트리의 성공 증거로 재사용하지 않았다.

보존할 방향: 검증 내용과 녹화 기록의 케이스 통합, TC 선택성, 실패/중단 기록 보존, 저장 후 사람 승인, 기록 기반 재생·필요 검증 AI·선택 healing 정책. 개선은 이 계약을 사용자가 이해하고 수행할 수 있도록 화면에 연결하는 작업이다.
